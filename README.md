# Resume Website

A responsive, JSON-powered resume and portfolio website for the **Recursion Resume Website assignment**. Uses native HTML, CSS, and JavaScript (ES modules) with no runtime framework and no npm dependencies. Includes project listing, individual case-study pages, skills/experience timeline, a downloadable **sample** PDF, and automated tests.

> **Template / public content notice:** The name `Your Name`, descriptions, example projects, dates, example email addresses, and downloadable PDF are **demonstration placeholders**, not verified personal work. Customize them before representing the website as a personal resume. Nothing in the source should be interpreted as a genuine employment or professional achievement claim.
>
> **Hosting notice:** Source code alone does **not** register a domain, deploy a live website, enforce production HTTPS, or guarantee uptime. The included GitHub Actions workflow can deploy after the owner enables GitHub Pages. See [deployment guide](docs/deployment.md).

## Features

- Semantic, keyboard-friendly home page explaining the website.
- JSON-driven project listing with instant search and category filters.
- Individual project views generated by a single detail template (`projects/detail.html?slug=...`).
- Resume page rendered from `data/profile.json` with a linked downloadable PDF.
- Responsive layout, mobile navigation, reduced-motion styles, safe text rendering.
- No API keys, cookies, database, required server runtime, or external style CDN.
- GitHub Pages workflow (`.github/workflows/deploy.yml`) and optional VPS guide.
- Comprehensive Japanese learning materials in `learning/`.

## Technology and requirements

| Component | Technology |
| --- | --- |
| UI | HTML5, CSS3, JavaScript ES modules |
| Data | Local JSON fetched by browser (`fetch` / AJAX) |
| Tests | Node.js built-in test runner and Python `unittest` |
| Local serving | Python 3 `http.server` or any static server |
| Optional deployment | GitHub Pages Actions, or VPS + Caddy |

Recommended: Node.js 18+ for automated JS tests, Python 3.9+ for local hosting and HTTP smoke tests. The **deployed site** itself needs only a modern browser and static HTTPS hosting.

## Run locally (Ubuntu / WSL2)

Open a terminal in the extracted `Resume-Website` folder:

```bash
cd Resume-Website
python3 --version
python3 -m http.server 8000 --bind 127.0.0.1
```

Open **http://127.0.0.1:8000/**. Stop the server with `Ctrl+C`.

Alternatively, `bash scripts/serve.sh`. Browsers may block `fetch()` for locally opened `file://` HTML pages, so **always serve with HTTP** when testing JSON rendering.

## Test

```bash
node --version
python3 --version
bash scripts/verify.sh
```

Or run suites separately:

```bash
node --test tests/*.test.js
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

No `npm install` is required. The Python tests start a temporary local HTTP server, verify important routes and the PDF, and shut it down.

## Customize

See [customization instructions](docs/customization.md), or open the site's `guide.html`. The two important data files are:

1. `data/profile.json`: replace `Your Name`, generic text, skills, achievements, and resume path with verified information.
2. `data/projects.json`: insert your actual projects; each entry must have a unique `id` and `slug`. Cards, filters, and details update automatically.

Replace the bundled sample resume PDF with an authentic document. Do not publish private contacts or credentials by accident.

## GitHub: first commit and repository creation

**Start from the project folder** after extraction, and confirm it does not contain a nested `.git` directory from another project. Git must be installed and configured (`git config --global user.name` / `git config --global user.email` if necessary).

```bash
git init
git status
cat .gitignore
git add .
git status
git commit -m "Initial commit: Resume Website"
git branch -M main
```

### Option A: GitHub CLI (simple)

After `gh auth login` (only if not already authenticated):

```bash
gh repo create Resume-Website \
  --public \
  --source=. \
  --remote=origin \
  --push
```

The repository **name contains hyphens, not spaces**. This command creates the repo and pushes commits. It does not automatically activate Pages hosting.

### Option B: GitHub website + Git remote

1. Open GitHub → **New repository**; name it `Resume-Website`, choose `Public` if required for the assignment, and **leave README/.gitignore/license unchecked** because the local repository already contains files.
2. Set its remote and push (substitute your real account in the URL):

```bash
git remote add origin git@github.com:<ACCOUNT>/Resume-Website.git
git push -u origin main
```

Use HTTPS instead of SSH if appropriate: `https://github.com/<ACCOUNT>/Resume-Website.git`; authenticate through the GitHub-supported flow or a credential manager (do not paste your password into a repository).

### Already created a repository?

Check `git remote -v` before adding `origin`; if it already exists, use `git remote set-url origin <URL>` rather than adding it twice. For subsequent changes:

```bash
git add .
git commit -m "Update portfolio content"
git push
```

`git status` should show a clean work tree after committing; verify uploaded files on GitHub rather than assuming the remote was updated.

### Publish the actual site

In **Settings → Pages**, select **Source: GitHub Actions**. The included workflow deploys on pushes to `main`. Confirm the Pages deployment URL in GitHub Actions. Custom subdomains and HTTPS setup are explained in [docs/deployment.md](docs/deployment.md). Actual cloud deployment and domain/DNS changes were **not performed** as part of the source generation.

## Troubleshooting

- **Project cards do not load**: use `http://127.0.0.1:8000/`, not `file://`; open DevTools Network and inspect `data/projects.json`.
- **JSON parsing error**: use `python3 -m json.tool data/projects.json` to locate malformed syntax.
- **Git says `remote origin already exists`**: inspect `git remote -v`, then `git remote set-url` if needed.
- **GitHub Pages shows a blank/404 URL**: enable Pages with GitHub Actions, wait for deployment, and confirm correct repository URL. Avoid absolute `/assets/...` paths when serving under a repository subpath.
- **Resume PDF contains sample data**: replace `assets/sample-resume.pdf` with a real resume before publishing.
